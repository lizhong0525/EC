# EcoTriage 可信度审计

日期：2026-10-20。适用版本：`ecotriage-v2.0.0`。这是一份工程审计，不是专家背书。

## 结论与实施顺序

旧工程确实实现了合成病例生成、三条 Track、规则策略、模型接口和实验报告，
但这些能力不等于一个经独立专家验证的 Benchmark。现存实验产物不能证明真实模型优势。
第一阶段只检验 Track A 的“当前可见证据下的下一步支持/转介动作”。

1. P0：隔离 v1 与 v2；消除模型侧语义 ID；完整请求封套泄漏回归；撤销旧 Hidden 保密推断。
2. P1：20 例开发材料双标、逐节点锁定、第三人裁决、审计与一致性门禁。
3. P2：专家行动规范与模拟状态恢复分开评分；无适用 Gold 则指标不可用。
4. P3：分组划分、近重复复核、协议冻结、病例聚类统计、匿名回复校准和发布隔离。

这些顺序已经落实为独立 `ecocompanion.research` 路径。历史路径保留，不自动迁移结果。

## 源码核验

| 检查 | 实际发现 | v2 处理 |
|---|---|---|
| 身份侧信道 | `benchmark/generation.py` 的 `case-rXX-eXX-xXX-pXX` 编入类别；`benchmark/llm_policies.py` 会发送 episode/evidence ID | 随机 UUID，固定保存映射；观察、历史、完整 provider request 一起检查 |
| 保密性 | 默认种子、模板、生成器与源码发布器都公开；不复制标签文件不足以保密 | v1 所有划分改称可重建公开开发/回归材料 |
| 旧 Gold 接入 | `experiments/report.py` 主要在证据路径读取专家资料，其他指标仍有生成器参考路径 | 新评分器仅从 Gold judgment 读取行动等级、动作、证据、对象、时窗 |
| Track A 公平性 | 旧历史可能包含先前策略回复，候选看到的完整输入并非始终相同 | 冻结学生历史；同一观察对所有策略相同 |
| Track B 假设 | `core/world.py`、`benchmark/track_b.py` 的信任、披露等变化是工程参数 | 只作为探索性引擎；提供参数压力测试与排名反转报告 |
| Track C 本地结果 | `benchmark/track_c.py` 本地路径按配置选择预写安全/不安全回复 | 明确是测试夹具/回归基线，不是模型能力比较 |
| 专家独立性 | 文档有计划，不能据此认定专家已经参加 | 20 例包初始无人工判断；资质与三人身份须管理员真实核验 |

`artifacts/cases`、`splits`、`runs`、`release` 等旧产物仅作为原有结果保留。
未重写其数据、分数或历史报告。新产物只写 `artifacts/research/` 的新路径。

## 已实现边界

- `identity.py`：可见输入、无语义映射、完整决策/回复 provider 封套审计；拒绝内部字段、
  编码 ID、风险/生态枚举和未知证据 ID。测试覆盖消息嵌套字符串。
- `annotation.py`、`api.py`、`annotation.html`：角色凭据、逐节点提交后锁定、第三人门禁、
  字段分歧、三人不同身份核验记录、哈希链与数据库不可更新触发器。
- `evaluation.py`：Gold 来源、覆盖、可见证据与导出审计校验；两个参考标准分栏。
- `governance.py`：按人物/骨架/来源/模板族连通分组；字符/精确检查和可插拔语义复核；
  独立材料私有导入、人工复核后接入，禁止自动生成数据冒充独立材料。
- `workflows.py`：仅取 legacy Train 的 20 例试标；源码与运行环境指纹冻结；四个离线诊断基线；
  盲测输出限 private；公开导出只白名单可见输入。
- `review.py`：候选匿名随机排序、专家/Judge 校准、严重违规人工复核队列。

## 未被工程实现证明的事情

无语义 ID 只能移除明确侧信道。公开开发病例本身仍可被模板匹配，不能借此声称独立性。
相似度阈值只能产生复核候选；未安装语义插件时必须保留 `NOT_RUN`。
独立病例来自真实管理员的外部收集与审查，程序只能核验契约和记录，不能证明来源叙述真实。

SQLite 触发器和哈希链用于发现意外更改，不抵抗拥有本机管理员权限的人重写整条链。
访问凭据由管理员分别交给三位专家；绝不能把整个工作区或 private 文件夹交给专家。
本机管理员可以读取全部材料，角色隔离不等于操作系统安全隔离。
如果用于跨机器协作，须先完成身份认证、TLS、访问审计、备份和伦理/数据治理审查；
默认 loopback 服务不是生产部署方案。

`qualified_api` 是严格结果导入契约，不是本次已执行的真实模型实验，也不是自动付费运行器。
它检查模型快照、协议绑定、预算、成本和禁止回退；外部调用日志真实性仍须独立审计。
Provider 封套检查不证明任意第三方 SDK 在传输层没有额外插入内容。
未调用付费模型，未上传材料，未开展真人研究。
