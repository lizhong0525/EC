# 网页 Benchmark 运行与报告

日期：2026-10-26。

## 网页入口

打开 `http://127.0.0.1:8002/`，进入 **Benchmark**。
左侧 **新建测试** 可以选择任务、案例数和对照策略，点击 **运行测试并生成报告**。
任务在后台运行，显示单元进度；完成后自动展示报告，可下载 Markdown 和 JSON。
已有运行尚无报告时，点击该运行即可生成报告。已生成的报告重复请求时直接读取，
不覆盖原文件。

本轮开放的是现有本地规则 Benchmark，不调用聊天模型或付费模型：

| 任务 | 网页配置 |
| --- | --- |
| Track A 风险与动作 | 开发集或公开测试集，1—24 案例，两个表层版本，各一次 |
| Track B 多轮交互 | 1—24 案例，每策略使用现有五个固定种子 |
| Track C 关系安全 | 1—12 场景，现有四种配置和五个固定种子 |

A/B 策略可选历史感知规则、关键词分流、始终倾听、始终升级。
模型身份、外部数据路径和 Hidden Test 不在网页启动参数内。
评分器、阈值、统计参数沿用现有实验实现，不从网页另造评分标准。
这些报告使用公开合成参考，不代表当前 Web 对话修订或 Qwen 模型的评测结果。

## 运行记录

当前网页的数据根目录为：
`artifacts/research/manual-web-test-20261026/`。

- `runs/<run_id>/`：不可覆盖的新运行、检查点、逐单元结果、报告。
- `benchmark-jobs/<job_id>.json`：任务配置、阶段与失败状态。
- 浏览器保存最近任务 ID，刷新或切换视图后可以继续查看进度。
- 服务重启后未完成的任务标记为中断，保留文件；新建任务使用新的运行目录。
- 单进程同一时间只执行一项测试或报告生成，不接受重复并发启动。
- 网页写操作要求研究模式、本机来源和受支持的浏览器 Origin。

更新服务时使用现有输出目录加 `--reuse-output`，
继续使用原数据库和聊天会话；省略该参数仍拒绝覆盖已有输出目录。

## 接口

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/v1/research/benchmark/jobs` | 创建有界本地测试任务 |
| `GET /api/v1/research/benchmark/jobs/{job_id}` | 读取阶段和单元进度 |
| `POST /api/v1/research/benchmark/runs/{run_id}/report` | 为已有运行生成报告 |
| `GET /api/v1/research/benchmark/runs/{run_id}/download?format=md` | 下载 Markdown，另支持 json |

沿用原有运行目录查询和报告读取接口。
运行 ID 按经过校验的目录清单解析，不接受用户指定文件路径。

- 新增后端回归：21 项通过，包含三 Track、下载、重复请求、并发、
  失败保留、重启中断、参数限制、来源限制和 Windows 原子替换重试。

  A/B/C 分别完成 6、15、20 个单元；这些是单案例流程检查。
- 浏览器无 pageerror，1440×1000 和 390×844 视口无整页横向溢出；
  宽报告表格在自身容器内横向滚动。

  本轮没有执行跨范围的自动升级。
