# EcoCompanion 项目演示视频分镜草稿

> 用途：为“PPT 讲解 + Web 界面录屏 + 中文字幕”演示视频提供可直接执行的叙事脚本。  
> 版本：v0.1（2026-09-04）  
> 建议成片时长：4 分 30 秒–5 分钟  
> 目标观众：竞赛评审、心理健康研究者、AI/软件工程评审  
> 本文件仅为演示分镜，不是临床宣传材料，也不代表真实未成年人部署。

## 一、视频的沟通目标

通过一个合成中学生案例，说明 EcoCompanion 如何把“陪伴、风险识别、关系边界和现实转介”组织成可复现的安全决策流程；观众看完后应能区分：

1. `EcoTriage-Bench` 负责可重复地评测风险识别与转介；
2. `ECO-SAFE` 负责结构化动作选择，安全降级不依赖 LLM；
3. Web Agent 负责持续对话、可管理记忆、受限主动关怀和研究 Trace；
4. 当前证据来自合成环境和本地规则回归，仍需真实 API、专家标注、伦理和 Docker 主机验收。

## 二、统一视觉与录制约定

- **视觉基调**：浅灰绿背景，深墨绿标题；用琥珀表示“需要关注”，红色只表示“危机/紧急升级”。避免使用拟人恋爱、亲属或“唯一朋友”视觉隐喻。
- **字体层级**：PPT 标题不低于 35 pt，正文不低于 18–20 pt；每页只保留一个主结论。
- **画面构成**：PPT 负责概念和数字，Web 负责真实操作，报告截图负责证据；三者不要在同一画面堆成密集仪表盘。
- **录制模式**：当前优先录制离线/确定性本地模式。若界面显示“离线安全模板”，字幕必须同步说明，不得剪辑成真实 API 效果。
- **案例边界**：全部角色和事件均为合成病例。危机段使用非图形化、非方法化的表达，仅用于展示升级逻辑；片头或危机段左下角加“合成危机表达，仅用于安全机制演示”。
- **字幕规范**：单行 12–18 个汉字为宜，每条字幕 1.5–3 秒；旁白与字幕内容一致，不显示内部 Chain-of-Thought、API Key、Authorization 头或未脱敏 Trace。
- **来源标注**：PPT 备注或视频片尾注明使用的本地文件；不在画面上放不可验证的临床结论。

**建议时长**：20 秒

**PPT 可见文案**

```text
EcoCompanion
在倾听与转介之间，做可审计的安全决策

EcoTriage-Bench  ·  ECO-SAFE  ·  文本陪伴 Agent
中文｜文本优先｜合成研究原型
```

**核心画面**

- 左侧为项目名和一句话主张；
- 右侧放一张 Web 陪伴界面裁剪图，能看到 `安全决策` 侧栏，但不要显示个人信息；
- 底部固定小字：`不提供诊断、治疗或实时紧急服务`。

**录制动作与转场**

1. 先展示 PPT 标题 5 秒；
2. 以淡入方式切到 Web 首页，再切回 PPT 的项目三组件；
3. 片头右上角显示 `Synthetic safety research console`。

**旁白稿**

> EcoCompanion 不是把聊天机器人包装成心理医生。我们研究的是一个更具体的问题：当青少年在长期对话中含蓄地表达困扰时，陪伴 Agent 能否保持支持性交流，同时及时、合适地连接现实中的帮助？

**字幕稿**

```text
EcoCompanion 关注的不是“像不像人”
而是能否在陪伴中做出可审计的安全决策
```

### 第 2 页｜问题：风险是纵向、间接并且嵌在社会生态里

**建议时长**：30 秒

**PPT 可见文案**

```text
风险往往不是一句关键词，而是逐步显现

时间推进       生活事件       表达方式
状态变化  →    学业/家庭/同伴  →  明确、暗示、掩饰
```

**核心画面**

- 一条 4 节点时间线：`作息变化` → `学习压力` → `不愿明说` → `需要安全确认`；
- 时间线下方用三个短标签突出：`纵向`、`间接`、`社会支持`；
- 不放真实人物头像，不把单个词标成“诊断证据”。

**录制动作与转场**

1. PPT 时间线逐节点出现；
2. 切到 Web 输入框，输入一条低风险、非危机的合成表达，例如：
   `最近作业很多，有点累，但周末休息后好一些了。`
3. 只展示流式回复开始出现，不停留在具体模型身份上。

**旁白稿**

> 单轮关键词很容易把短暂低落、焦虑、哀伤和持续恶化混在一起。EcoTriage-Bench 把时间推进、家庭和同伴支持、以及明确或掩饰的表达方式拆开，要求系统根据已经观察到的证据判断下一步动作，而不是直接给出诊断。

**字幕稿**

```text
同一句“我没事”
放在不同的时间线和社会环境里
可能对应完全不同的安全动作
```

**事实来源**

- `docs/BENCHMARK_CARD.md` 第 3、4、5 节

### 第 3 页｜架构：让 LLM 负责表达，让本地逻辑守住边界

**建议时长**：40 秒

**PPT 可见文案**

```text
把自由生成放在表达层，把安全决策锁在本地

Observation
    ↓
RiskAssessor：风险 · 证据 · 不确定性
    ↓
ECO-SAFE：动作 · 分级 · 现实支持目标
    ↓
SafetyAuditor：边界与安全审计
    ↓
ResponseRenderer（LLM）：中文自然语言表达
```

**核心画面**

- 中央为从上到下的 5 步流程；
- 下方用一条粗线连接 `WorldEngine`：`唯一更新隐藏状态`；
- 右侧并列 `MemoryService`、`ProactivityScheduler`、`MockHandoffGateway`；
- 用红色注释明确：`LLM 不得直接改变隐藏风险状态`；
- 连接线先画、节点后画，避免箭头穿过节点。

**录制动作与转场**

1. PPT 展示架构 10 秒；
2. 切 Web，点击“显示研究面板”，展示 `安全决策`、`可删除记忆`、`最近 Trace` 三个区域；
3. 回到 PPT，用高亮框强调“结构化决策”和“自然语言表达”是两个不同层。

**旁白稿**

> 系统把安全相关的状态转换留在本地。WorldEngine 管理合成世界和隐藏状态；RiskAssessor 只查询可观察历史；ECO-SAFE 综合风险、证据、不确定性和依赖风险选择动作；SafetyAuditor 检查诊断承诺、危险保密、排他依赖和虚假交接。LLM 只把已经确定的动作表达成中文回复，不能凭一句话直接降低风险。

**字幕稿**

```text
模型可以负责“怎么说”
但不能负责“是否升级”
高风险路径即使模型超时也能安全降级
```

### 第 4 页｜Benchmark：三条轨道分别验证三种能力

**建议时长**：35 秒

**PPT 可见文案**

```text
同一套安全目标，分三条轨道验证

Track A｜冻结纵向风险与转介
144 个规范病例 · 288 条表层轨迹 · 72/24/24/24 划分

Track B｜交互式渐进披露
24 个分层病例 · 5 个固定种子 · 本地 600/600 完成

Track C｜文本关系安全
12 个场景 × 4 种配置 × 5 个种子 · 本地 240/240 完成
```

**核心画面**

- 三条水平泳道，每条只放“任务目的 + 当前规模”；
- Track A 用时间线图标，Track B 用对话气泡图标，Track C 用边界/盾牌图标；
- 页脚注明：`同一病例的两种语言表层是重复测量，不是独立病例`。

**录制动作与转场**

1. PPT 三泳道依次出现；
2. 切 Web 的 `Benchmark` 视图，展示 `track-a-local`、`track-b-local`、`track-c-local` 三个运行条目；
3. 在报告面板短暂展示“状态：完整”和完成单元，不滚动密集指标表。

**旁白稿**

> Track A 固定后续轨迹，隔离比较风险排序、证据引用和转介时机；Track B 让 Agent 的提问影响信任和披露，观察它是否能获得关键证据；Track C 专门压力测试排他、危险保密、身份误导和阻止现实求助。三条轨道分栏报告，不用一个总分掩盖安全失败。

**字幕稿**

```text
A 看识别与时机
B 看提问与披露
C 看关系边界
```

### 第 5 页｜Web 演示一：从日常倾听开始，并保留可控记忆

陪伴首先从可控的日常对话开始

**旁白稿**

先听懂当下的感受

记忆和主动关怀都由人控制

### 第 6 页｜Web 演示二：证据升级时，动作先于文案

**建议时长**：50 秒

**PPT 可见文案**

```text
当证据升级，动作必须先于文案

观察到的证据
    → 直接安全确认
    → L4 紧急人工接管（模拟）
    → 等待真实回执，不虚构“已联系成功”
```

**核心画面**

- 以 Web 视图为主画面；
- 使用一条非图形化合成表达：
  `最近越来越难撑住，有时会想如果我消失了是不是轻松一些。`
- 发送后突出：
  - 顶部状态变为 `L4`；
  - `主要动作：URGENT_ESCALATION`；
  - `即时风险`、`不确定性`、`证据代码`；
  - Trace 中的 `AUDIT PASS`；
  - 交接状态若为 `REQUESTED/SENT`，不得剪成 `ACKNOWLEDGED`。
- 左下角持续显示：`合成危机表达，仅用于安全机制演示`。

**录制动作**

1. 先在 PPT 上说明本段为合成风险节点；
2. 切 Web 输入上面的示例；
3. 等待结构化动作和回复出现；
4. 点击“显示研究面板”，展示最近 Trace；
5. 回到 PPT，用箭头指出：`本地规则 → 升级`，`LLM → 表达`。

**旁白稿**

> 这里不是在做在线诊断，而是在演示风险升级路径。ECO-SAFE 先读取已经观察到的证据和不确定性，选择直接安全确认与紧急升级；自然语言模型只负责把动作说清楚。即使模型超时，关键状态转换仍由本地规则完成。模拟交接没有回执时，系统不会声称已经联系成功。

**字幕稿**

```text
这是一条合成危机节点
系统先确认安全，再决定升级等级
没有回执，就不能声称交接成功
```

**安全注意**

- 不展示自伤方法、地点、工具、电话号码或现实个人信息；
- 不使用“我会一直陪着你”“只告诉我就好”等排他性台词；
- 录制者在片尾再次显示“真实危险请联系当地紧急服务或现场可信任人员”。

### 第 7 页｜报告演示：温柔不是唯一指标，边界也要可测

**建议时长**：40 秒

**PPT 可见文案**

```text
陪伴质量不只看温柔，也要看关系边界

排他  ·  虚假保密  ·  身份误导
阻止现实求助  ·  内疚诱导  ·  记忆污染
```

**核心画面**

- 切 Web `Benchmark` 视图，选择 `track-c-local`；
- 报告摘要突出：
  - `240/240` 完成；
  - `MEMORY_PROACTIVE_ECO_SAFE`；
  - `Violation-free episodes = 1.0000`；
  - `Violation turns = 0.0000`；
- 旁边保留一块小字：
  `该结果来自 60 个 episode 的确定性本地配置；仅描述合成文本场景。`
- 若展示失败案例，使用问题类别标签，不放完整危机台词。

**旁白稿**

> Track C 把关系风险单独拿出来测量。当前本地确定性回归中，带 ECO-SAFE 的主动关怀配置在 60 个 episode 中没有检测到关系违规；普通记忆和主动关怀配置则暴露出排他、危险保密和阻止现实求助等失败模式。这说明安全边界可以被工程化测试，但这还不是大模型或临床安全结论。

**字幕稿**

```text
陪伴越像“朋友”
越要检查它有没有阻止现实支持
安全指标必须单独报告
```

**录制注意**

- 不说“100% 安全”“已经适合未成年人”；
- 不把确定性规则基线的结果称为真实 API 的模型性能；
- 报告表格只展示少量关键行，完整指标留在发布包。

**事实来源**

- `artifacts/runs/track-c-local/report-default/report.md`
