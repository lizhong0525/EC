# 外部参考补全与审计协议

版本：`external-reference-completion-v1.0.0`。日期：2026-10-22。
这是新增的离线描述性审计，不修改 `external-reference-v1.1.0` 的冻结协议，
也不是新增预注册实验、专家 Gold 或模型验证通过声明。

## 交付边界

本轮优先补齐无需专家、无需模型下载、无需材料外传即可完成的两项工作：

1. VERA 固定评分表的路由审计、严格答案路径重放与逐维原始人工一致性诊断。
2. PsyCrisis 冻结任务包的逐维参考支持量、输入分组与不确定性解释。

原 backend、三份冻结外部参考脚本、历史报告和任务包均保留。
新增脚本通过既有解析器和验证接口读取材料，不执行上游 Python。
工程夹具、上游人工标签、新模型输出和项目行动规范 Gold 分开记录。

## VERA 路由检查

入口：`scripts/vera_flow_audit.py`。
只接受已固定的 VERA 快照，并验证 Git 对象、文件清单及摘要。
使用 TSV 结构解析器检查问题编号、维度、严重度、答案选项与跳转目标；
遍历分支，拒绝不可达问题、循环及悬空跳转。

本地 `replay` 仅接受外部提供的完整、精确答案序列，不从对话推断答案：

- 未完成路径返回 `INCOMPLETE`，分数为 null。
- 答案必须与列出的选项完全一致；不做子串匹配，不默认选第一项。
- `END`、`ASSIGN_END`、`NOT_RELEVANT>>` 分别处理，不把不适用计成安全。
- 保存实际路径与预期路由；预置路由用例明确标成程序契约，不是专家评审。

上游 AST 检查只报告所审查函数中的局部行为，不宣称全程序安全证明。
本地严格解析故意不同于上游宽松答案回退，不能声称逐字复刻原 Judge。
结构检查通过不自动解除既有 VERA live Judge 门禁。
论文实验所用的精确 rubric、客户端历史和推理配置尚未完全核验。

## 原始人工一致性

每段对话必须有三名不同原评分者、同一个人物模板和合法评级。
逐维保留全部三人的原始答案计算 nominal Krippendorff alpha。
无类别变化等无法定义的情形保留 null，不记为满分。
三票不同时保留 Unresolved，不删例或猜测专家角色。

每维单独报告：

- 四类原始评分频数、派生多数参考频数、未决数和全票一致数。
- 两两一致比例；每段三次配对不是三个独立病例。
- 按对话整体 bootstrap 的 alpha 区间。
- 按人物模板整体 bootstrap 的敏感性区间。
- 多数参考中未覆盖的类别，避免向零支持类别外推。

沿用已有统计函数：1,000 次 percentile bootstrap，种子 20261021，
95% 描述性区间；记录有效重采样次数。只有 10 个模拟人物模板，
既不代表 10 个真实独立人物，也不能证明跨语言或青少年适用性。
这些统计衡量原人工之间的一致性，不是本地 Judge 的准确率。

## 参考支持量检查

入口：`scripts/reference_support_analysis.py`。
复用冻结任务包验证、原始五维标签契约和分组隔离检查。
分别计数阳性回复和阳性输入组，输入组不能冒充经核验的独立人物。
检查结束重新验证任务包；审计脚本也保存自身摘要并检查运行中变化。
这是开始和结束的完整性检查，不是事务快照或抗恶意并发篡改证明。

保持原两阶段各维正负参考至少 20 条、覆盖率 1、
正例 F1 和召回均至少 0.80 的工程筛查不变。
不自动去掉维度、移动分区、复制标签或用模型标签填补人工参考。
支持量不够与尚无模型推理是两件事，必须分别报告。

输出中的 Wilson 区间只是假设独立伯努利试验的教学示例。
它不是实际模型结果、不是分组置信区间，也不是临床样本量或效能分析。
存在重复回复、人物或模板依赖时，不得直接套用示例区间。

## 运行与复核

在项目根目录执行，每轮使用全新的输出目录：

```powershell
$py = '.research-venv/Scripts/python.exe'
$out = 'artifacts/research/completion-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
& $py -X utf8 -m scripts.vera_flow_audit --output "$out/vera-flow"
& $py -X utf8 -m scripts.reference_support_analysis --output "$out/reference-support.json"
& $py -X utf8 -m scripts.p0_validation doctor --output "$out/doctor"
```

前两项不调用模型、不连接外部服务。`doctor` 只探测既有本机模型服务，
不下载、不推理、不回退。既有输出拒绝覆盖。
将前两项再运行到另一个新目录，可比较 `audit.json`、`rubric-structure.json`
及 `reference-support.json` 的 SHA-256。时间戳化的服务预检不要求字节相同。
同机同版本的确定性重放不能替代跨环境复现。

## 仍需外部条件

| 工作 | 负责人或条件 | 完成证据 |
|---|---|---|
| 600 条校准与 200 条公开留出 Judge 实验 | 用户确认模型安装/下载；研究工程运行 | 精确模型摘要、全部请求/输出/失败、独立重算 |
| 原五维支持量缺口 | 数据管理员与适用的原人工参考；另立版本 | 来源与权限、标签匹配、分组审计，不是 AI 补标 |
| 真实目标 Agent 主实验 | 明确模型、预算和实验条件 | 不同于 Judge 的冻结与执行记录 |
| VERA 新 Judge | 研究版本和客户端等价性进一步核验 | 新协议、新任务包与原人工参考对照 |
| 行动、时间窗与证据 Gold | 真实合格专家独立双标及裁决 | 身份/角色核验、锁定原记录、来源可追溯 |
| 独立盲测与授权/隐私复核 | 独立数据管理员及权限持有人 | 来源独立、不可由公开生成器还原、访问与发布隔离 |
| Windows 文件隐私保证 | 专门的 ACL 实现与验证版本 | 真实 ACL 证据，不以 POSIX 模式位冒充 |
| Docker 冷启动 | 可运行的 Docker daemon 与构建环境 | 镜像构建、健康检查和干净环境启动记录 |

没有专家时，可以完成外部原任务的探索性研究，但不能声称已经完成项目特有
的专家行动规范 Benchmark。未开展真人研究，也不把伦理审批列为工程可代办事项。
