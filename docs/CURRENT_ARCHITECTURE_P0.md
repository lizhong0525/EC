# 当前架构与 P0 验证入口

日期：2026-10-21。本文件描述实际源码，不代表真实模型实验或临床验证已完成。
本轮 P0 指外部参考路线的运行就绪与校准启动，不替代历史 P0/P1 测量协议。

## 1. 一句话说明

这是一个心理支持 Agent 的研究与评测平台，不是一套自行训练完成的心理大模型。
主路径由规则判断风险、ECO-SAFE 决定下一步动作，再由模板或可选的大模型组织语言。
离线 Judge 是另外一个评审角色，不是对话 Agent，也不能生成真实专家 Gold。

## 2. 主路径

```text
当前消息 + 截至当前的对话历史 + 允许动作
                      |
                ObservationV1
                      |
          RuleBasedRiskAssessor
          关键词/短语匹配、权重累加
                      |
       三类信号分数 + 证据引用 + 不确定性
                      |
                ECOSafePolicy
          固定阈值和优先级选择结构化动作
                      |
       模板 / 可选 LLMResponseRenderer
                      |
      SafetyAuditor + 会话状态/边界检查
                      |
             回复 + 保存执行轨迹
```

- `backend/src/ecocompanion/core/risk.py`：规则风险评估。
  三个数值分别对应情绪恶化、即时安全和依赖信号。
  它们是规则分数，不是经过临床校准的患病概率。
  不确定性也由证据数量等启发式计算，不是已验证的统计置信度。
- `backend/src/ecocompanion/core/policy.py`：动作决策。
  优先即时危险升级，其次直接安全询问、关系边界、专业评估、可信成人支持、
  补充询问和倾听。阈值是代码配置，不是本轮验证出的临床界值。
- `backend/src/ecocompanion/benchmark/policies.py`：Benchmark 的规则基线、
  ECO-SAFE 及其消融开关。未提供 provider 时使用本地模板。
- `backend/src/ecocompanion/application/renderer.py`：可选 LLM 只将已经确定的动作
  写成自然中文；不能据此称它完成了风险推理。演示服务有明确的模板降级路径，
  不能把降级回复当作真实模型实验输出。
- `backend/src/ecocompanion/application/service.py`：会话编排、记忆、状态、
  输出审计、主动关怀限制与模拟交接；模拟交接不是已接通真人。

另有 `benchmark/llm_policies.py` 的直接 LLM 决策基线：可以用当前消息、完整历史、
可见历史投影记忆等不同条件，要求模型返回结构化决策。这与主路径中
“LLM 只负责表达”是两种不同的实验条件，不能混写成一个模型架构。
现有接入代码不证明已经对特定真实模型做过正式实验。
在本轮检查的 backend、scripts、web 与依赖定义中未发现本项目训练或微调模型的实现；
不能将这里的系统架构称作自研神经网络架构。输出审计也是规则检查，
并不保证识别所有上下文中的风险、隐喻、否定或不当建议。

## 3. 验证路径

```text
固定来源数据与原人工评分
             |
      不可覆盖的冻结任务包
             |
     P0：完整性、分组与支持量检查
             |
    显式安装/选择本机 Judge，冻结摘要
             |
  600 条校准 -> 200 条公开留出
             |
  相同配置、五维完整覆盖/性能/支持量门禁
             |
  通过后才可评审 3,040 条项目历史回复
```

- PsyCrisis：参考只适用于原输入、原回复的五种回复要素。
- VERA-MH：当前复核原始临床人员之间的一致性，不是本地 Judge 的一致性。
- CRADLE：原生危机事件识别，不是行动合理性 Gold。
- 项目行动规范：必须有输入匹配的适用参考；目前仍不可用。
- 模拟隐藏状态恢复：与上述参考分开，不能当真实诊断或真实结局。

`scripts/local_reference_judge.py` 只允许固定回环地址的 Ollama。
`scripts/p0_validation.py` 新增外围编排，不修改冻结脚本、backend 或旧任务包。
它自身的摘要另存于 preflight；旧任务包的完整性摘要不被重新签写。

## 4. 可运行的 P0

从项目根目录执行。每次使用新输出目录，已有路径拒绝覆盖：

```powershell
$py = '.research-venv/Scripts/python.exe'
$out = 'artifacts/research/p0-local-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
& $py -X utf8 -m scripts.p0_validation doctor `
  --output "$out/doctor"
```

`doctor` 核验当前实现/运行环境与任务包的一致性、逐维支持量，
并探测本机模型列表。它不生成任何 Judge 分数、不选择或下载模型、不读密钥。
检查后保存 `probe.json`、`preflight.json`、`summary.json`。

在明确安装并选定本地模型后，使用其精确名称：

```powershell
& $py -X utf8 -m scripts.p0_validation run `
  --model EXACT_INSTALLED_MODEL:TAG `
  --output "$out/local-run"
```

该命令先检查、再冻结模型，按顺序执行完整校准和公开留出。
每条任务最多一次推理，零重试；首次失败后停止，缺失保留在分母。
校准完成但性能不通过时仍可做公开留出测量，不能据此放行项目回复。
只有额外显式提供 `--include-project` 且两阶段全部通过，才会启动项目回复评审。
这不启动真实目标模型的主实验，也不进行 VERA 新 Judge 复现。

新入口不改变五维门禁。当前公开留出中的 `risk_inquiry` 只有7个参考阳性，
低于冻结的20个工程支持量要求；因此五维联合放行在本版数据上不可达。
差13条是当前分区下的参考回复数量缺口，不是“再凑13个病例就有统计效力”的结论；
原参考总共28个阳性，也不足以同时满足两个分区各20个。
不能复制、移动原标签、根据结果换阈值或用AI标注冒充新增人工参考。
改任务范围、增加新来源或采用新的交叉验证研究设计必须另立版本，
披露旧材料的使用，不将旧公开留出重新包装成未知测试集。

## 5. P0 完成标准

| 层次 | 达成条件 |
|---|---|
| 工程就绪检查 | 完整性与分组检查执行、阻断原因明确、失败/覆盖与旧记录保护经过测试 |
| Judge 校准实验 | 精确模型身份冻结，600+200条实际推理与独立重算完成 |
| 项目自动评审放行 | 两阶段五维全部通过原门禁；不是安全认证 |
| 真实目标模型实验 | 另行冻结模型、提示词、预算、运行与评分 |
| 行动规范或临床结论 | 当前数据与自动评审不能补齐，仍不支持此类结论 |

运行就绪不等于校准通过，程序测试通过不等于有新模型结果。
本轮实际执行和限制见 `P0_READINESS_RESULTS_20261021.md`。
