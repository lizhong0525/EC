## 1. 动机

该数据集用于研究一个纵向心理陪伴 Agent 如何在支持性对话中逐步发现风险证据、
表达不确定性并连接现实支持。它刻意覆盖间接表达、掩饰、社会生态差异和转介时机，
以补充只对单轮显式危机语句做分类的评测。

数据集不用于训练或验证临床诊断器，也不用于估计真实青少年群体的患病率、病程或
治疗效果。

## 2. 数据集由谁创建

当前版本由 EcoCompanion 项目的确定性病例生成器和人工编写的中文模板产生。
正式 v1 计划由两名心理专业专家独立标注，第三名专家裁决高风险病例和其他分歧。
在专家流程完成、记录资质范围并冻结标注手册前，当前标签仅是研究草案。

数据集未复制 `Adolescent-Depression-Simulator` 的源码或数据。上游仓库仅作为
角色、社会生态事件和时间推进思想的概念参考；由于核验时未展示许可证，本项目
采用洁净重写。

## 3. 数据组成

### 3.1 规范病例

确定性生成器采用完整析因设计：

```text
6 风险轨迹 × 4 社会生态 × 3 表达方式 × 2 规范复本 = 144 病例
```

当前实现每个病例包含 14 个决策节点，模拟时间从 `day-01-evening` 开始，每两天
推进一次，最后一个节点为 `day-27-evening`。每个节点包含两种冻结中文表层表达。

| 数量 | 当前值 |
|---|---:|
| 规范病例 | 144 |
| 规范病例轨迹（含两种表层） | 288 |
| 规范决策节点 | 2,016 |
| 可观察表层节点 | 4,032 |
| 每病例披露事实槽 | 5 |

### 3.2 因素

风险轨迹：

- `TRANSIENT_LOW_MOOD`
- `NON_DEPRESSIVE_DISTRESS`
- `PERSISTENT_SUBCLINICAL`
- `GRADUAL_WORSENING`
- `SEVERE_NON_ACUTE`
- `ACUTE_CRISIS`

社会生态：

- `FAMILY_SUPPORT`
- `PEER_OR_TEACHER_SUPPORT`
- `FAMILY_CONFLICT`
- `LOW_OVERALL_SUPPORT`

表达方式：

- `EXPLICIT`
- `INDIRECT`
- `MASKED_OR_CONTRADICTORY`

所有角色均为 12–15 岁、`zh-CN` 的合成人物标签，不对应真实学生。

### 3.3 一个病例包含什么

公开结构遵循 `CaseSpecV1`：

- 病例 ID、Benchmark 版本和合成标记；
- 风险轨迹、社会生态、表达风格；
- 可见年龄组、语言和已披露背景；
- 合成人格标签与事件模板家族；
- 可渐进披露的事实及最早可用节点；
- 动作的最早、最佳和最迟窗口；
- 逐节点事件、两种冻结表达、隐藏状态和动作构造标签。

六类 Benchmark 核心 JSON Schema 以及三类外部日志导入辅助 Schema 位于
`artifacts/schemas/`。

## 4. 实例是什么

不同 Track 的实例单位不同：

- Track A：一个规范病例的一种语言表层轨迹；
- Track B：一个规范病例、固定种子和策略构成的交互 episode；
- Track C：一个关系边界压力场景、系统配置和固定种子构成的 episode。

论文统计时，Track A 的两种表层不得作为独立病例。Track B/C 的多个种子也应作为
同一场景的配对重复。

## 5. 数据如何生成

### 5.1 确定性

规范病例由本地 Python 代码生成，不需要外部模型 API。生成器使用固定基础种子，
并把基础种子与风险轨迹、社会生态、表达方式和复本编号进行稳定哈希。相同代码、
配置和种子应产生字节语义等价的病例。

正式发布 Manifest 应记录：

- 生成器代码版本或 Git commit；
- Python 与依赖版本；
- 基础种子；
- Schema 哈希；
- 病例文件 SHA-256；
- 划分 Manifest SHA-256；
- 标注手册版本与哈希。

### 5.2 隐藏状态

当前隐藏状态字段为：

```text
depression_burden
acute_safety_risk
trust_in_companion
disclosure_readiness
offline_help_willingness
ai_dependency
family_support
peer_support
school_support
```

这些值是模拟引擎变量。它们不是 PHQ-9 分数、临床诊断概率或真实治疗结果。
被测 Agent 只能收到 `ObservationV1` 中的可见内容，不得访问隐藏状态。

### 5.3 语言表层

两种表层由人工模板和确定性表达风格变换产生。当前规范病例不使用 LLM 做必要
语言生成，因此不会因上游模型更新而漂移。若后续引入 LLM 改写，应：

1. 固定模型快照、Prompt、参数和种子；
2. 要求输出只表达规范事实；
3. 进行事实一致性人工复核；
4. 把同一规范病例的全部改写绑定到同一划分；
5. 在 Datasheet 中单独标识 LLM 生成内容。

### 5.4 外部合成日志导入

可选外部模拟器数据必须先转换为版本化的中立
`ExternalEventLogRecordV1` JSON/JSONL 契约，再由
`eco benchmark import-log` 生成 `ImportedCaseDraftV1`。该流程只保留人物可见
信息、模拟时间、可见事件和话语，并进行凭据与直接联系方式脱敏。

导入草稿固定为 `PENDING_EXPERT_RELABEL` 和 `benchmark_eligible=false`，不包含
隐藏状态、风险标签、动作标签或干预窗口。草稿必须按标注手册重新进行专家标注，
不得直接并入任一正式数据划分。完整契约见 `docs/EXTERNAL_LOG_IMPORT.md`。

## 6. 标签

### 6.1 当前构造标签

生成器为每个节点产生：

- 隐藏风险状态；
- 可接受动作集；
- 优选动作；
- 禁止动作；
- 干预窗口；
- 可披露事实和证据码。

这些标签用于引擎开发和回归测试，不应在未经专家复核时称为临床专家标签。

### 6.2 正式专家标签

正式发布预期包含：

- 风险等级及置信度；
- 支撑证据 ID；
- 可接受动作集、优选动作与禁止动作；
- 是否需要直接安全询问；
- 最早、最佳和最迟转介节点；
- 转介等级及安全对象；
- 模型回复的安全与支持性盲评。

标注流程见 `docs/ANNOTATION_GUIDELINES.md`。

## 7. 推荐数据划分

规范划分为：

| 划分 | 病例数 | 推荐用途 |
|---|---:|---|
| Train | 72 | Prompt、规则或可公开训练开发 |
| Dev | 24 | 阈值选择和误差分析 |
| Public Test | 24 | 可复现实验与公开排行榜 |
| Hidden Test | 24 | 盲测；不得公开标签 |

当前划分算法把每个析因格的第一个确定性复本放入 Train，第二个复本通过平衡轮换
进入 Dev、Public Test 或 Hidden Test。它保证病例 ID、规范病例和两种表层不跨集。

### 7.1 泄漏审计

两个规范复本使用独立语言和事件模板族。`eco benchmark validate` 当前执行：

1. 病例、表层、事件模板族和人格标识的跨划分归属检查；
2. 规范化 utterance、事件文本和人格标识的精确指纹检查；
3. utterance 与外部事件的字符 3-gram Jaccard 跨划分全量比较；
4. 将完整近重复审计写入 `BenchmarkValidationReport` 和发布包。

当前固定数据在阈值 `0.85` 下没有跨划分近重复文本对。Train 对 Dev/Public/Hidden
的 utterance 最大相似度分别为 `0.4000`、`0.4000`、`0.4247`；全部划分组合中的
最大值为 `0.7500`。这些数值证明当前工程规则下没有高相似近重复，不证明不存在
语义同构、模板风格偏差或对真实对话的分布偏移。任何病例文本、模板、划分或规范化
算法变化都必须重新运行审计并产生新的数据版本。

## 8. 收集、同意与隐私

- 规范数据不来自真实学生、病历、社交媒体或咨询记录；
- 不存在真实参与者的知情同意问题，因为数据完全合成；
- 不应向合成病例加入真实姓名、学校、地址、账号、联系方式或可识别经历；
- 成年参与者可用性研究属于单独数据源，不能混入 Benchmark；招募前需获得适用的
  伦理审批和知情同意；
- Trace 发布前必须移除 API 密钥、Authorization 头、环境变量、自由形式推理和
  成年测试者的可识别信息。

## 9. 数据质量控制

正式发布至少执行：

- 所有 JSON/JSONL 通过对应 Pydantic 模型和 JSON Schema；
- 病例 ID、节点 ID、观察 ID 和事实 ID 唯一；
- 节点从 0 连续递增；
- 每节点至少两种语言表层；
- 可披露事实必须属于病例事实集合，且符合可用节点；
- 可接受动作与禁止动作不相交；
- 优选动作属于可接受动作；
- 干预窗口顺序合法且不超出轨迹；
- 144 病例完整覆盖 6×4×3×2；
- 四个划分互斥并覆盖全部规范病例；
- 相同种子生成结果一致；
- 隐藏字段不出现在 `ObservationV1`；
- 跨划分模板、精确文本和字符 3-gram 近重复审计通过；
- 专家一致性达到手册门槛；
- 秘密扫描和敏感字段扫描为零。

Hidden Test 标签应由评测服务或受控脚本持有，不能进入公开发布包。

`eco benchmark package` 默认会在 `models/` 写入明确的模型快照待补占位说明；只有
显式提供现有快照时才复制 `model_snapshot.json`。显式传入运行目录后，构建器只复制
可识别的 Manifest、结果、原始输出和 Trace 文本，并在写入包前移除凭据和 Trace 中的
隐藏状态；缓存、数据库、未知二进制文件会被保留在包外。每个组件的状态和路径见
`RELEASE_MANIFEST.json`，逐文件校验由 `scripts/verify_release.py` 完成。

当前仓库忽略运行 Trace、缓存、本地数据库和模型快照。只有经过脱敏、审核和明确
版本化的产物才能进入正式发布；自动脱敏并不替代人工发布审查。

## 11. 维护与版本策略

- 代码包采用语义化版本；
- Benchmark 数据采用独立的 `ecotriage-vMAJOR.MINOR.PATCH`；
- 修正文案但不改变标签语义可增加 PATCH；
- 新增病例、模板或指标通常增加 MINOR；
- 改变风险定义、动作本体、划分或统计单位需要增加 MAJOR；
- 已发表实验使用的数据版本不得原地覆盖；
- 发现安全问题、隐私问题或测试泄漏时，应保留公告、影响范围和修复版本。

维护者、问题反馈渠道和许可证必须在首次公开发布前写入 Manifest。本草案不推定
尚未声明的许可证。

## 12. 已知偏差和限制

- 合成模板可能高估关键词策略，低估真实对话中的方言、错别字、沉默和语用差异；
- 12–15 岁只是角色设定，未经过真实青少年语言验证；
- 社会生态被压缩为四类，不能覆盖文化、城乡、经济和家庭结构差异；
- “现实支持”是否安全具有情境性，不能默认家长总是合适对象；
- 急性风险场景数量由析因设计决定，不代表真实流行率；
- 模拟依赖状态不能替代真实长期使用研究；
- 自动 Judge 可能共享模型偏差，必须由专家评分校准；
- 当前没有证据支持跨语言、跨文化或临床部署泛化。
